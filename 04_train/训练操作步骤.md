# AutoDL 上跑通训练 —— 操作步骤

> **这一轮的目标是「管线能跑」，不是「模型好用」。**
>
> 23 条数据训出来必然是背答案。这一轮的产出是：一套验证过的环境 + 一条验证过的
> 数据格式 + 一个基线 loss 曲线。等数据攒到 200 条，同一套东西直接复用。
>
> 前置阅读：[方案v2-修正版.md](../方案v2-修正版.md) 第三节（为什么不能急着 SFT）

**总成本约 ¥2**，全程约 1.5 小时（其中大半在等下载）。

## 机器选型

| GPU | 显存 | 约 ¥/h | 这一轮够不够 |
|---|---|---|---|
| **RTX 4090** | 24GB | ~2.0–2.7 | ✅ **选这个**。Qwen3-8B QLoRA 4bit 绰绰有余 |
| RTX 3090 | 24GB | ~1.3–1.7 | ✅ 也行，慢一些，更省 |
| A800 | 80GB | ~5.6 | 以后跑 bf16 LoRA / 14B 时再用，现在是浪费 |
| RTX 5090 | 32GB | ~3.5 | ⚠️ 别选。新架构 bitsandbytes 兼容性时有问题，排查成本高 |

**镜像随便选，但驱动要 ≥ 525**（4090/3090 的机器都满足）。镜像自带的 Python 版本不用管——
`autodl_setup.sh` 会自己在数据盘上建 Python 3.11 环境，不碰镜像的 base。

> 💡 **省钱关键**：步骤 2–5（装环境、下模型、注册数据）**全在「无卡模式」下做**，¥0.1/h。
> 只有步骤 6–8 真正需要 GPU。开着 4090 等 16GB 下载完是这一轮最容易白花的钱。

<details>
<summary>为什么要自建 Python 环境（踩过的坑，展开看）</summary>

LLaMA-Factory 主线要求 **Python ≥ 3.11**，而 AutoDL 有大量 Python 3.8 的老镜像——
包括那些标了 `torch_env` 的，里面也是 3.8。版本不够时你看到的报错是：

```
ERROR: No matching distribution found for accelerate<=1.11.0,>=1.3.0
```

看着像镜像源不全或网络问题，其实是 pip 按 `requires-python` 把新版本全筛掉了，
`from versions:` 那个列表里最高只到 1.0.1。极易查错方向。

**不要**用 `git checkout` 退到支持老 Python 的 LLaMA-Factory 版本——那是 2024 年的代码，
没有 `qwen3_nothink` 模板。填错模板不报错，只是训出来的东西是废的。

</details>

## 步骤 3：AutoDL —— 装 LLaMA-Factory

仓库直接在实例上拉，比 scp 省事（也躲开 Windows 下路径带空格和中文的坑）：

```bash
cd /root/autodl-tmp
git clone https://gitee.com/shice_health_0/sft.git
bash sft/销售会议抽取/04_train/autodl_setup.sh
```

脚本做七件事：查驱动 → 缓存挪数据盘 → clone LLaMA-Factory → 建 Python 3.11 环境 →
装依赖 → 自检 → 建工作目录。约 3–8 分钟。

**自检要看这几行**：

```
torch        2.6.0+cu124  (CUDA 12.4)
CUDA 可用     False            ← 无卡模式下是 False，正常
transformers 5.x.x
bitsandbytes 0.5x.x  ✅ QLoRA 可用
CUDA 13 残留  无 ✅
```

> ⚠️ 如果 `bitsandbytes` 报错，QLoRA 跑不了。改用 A800 80GB 跑 bf16
> （删掉 yaml 里的 `quantization_bit` / `quantization_method` 两行）。

<details>
<summary>脚本里有两处刻意的设计，改之前先看这里</summary>

**① 用 uv 而不是 pip。**
LLaMA-Factory 的依赖范围开得很宽（`transformers>=4.55.0,<=5.8.0,!=4.57.0,!=5.6.0` 这种）。
pip 的回溯式解析要下载大量候选 wheel 只为读元数据，实测**卡了 20 分钟不出一行声**
（`-q` 还把进度吞了，看着像死机）。uv 同样的解析 3 分钟出头。
LLaMA-Factory 官方自己也是拿 uv 当包管理器的。

**② torch 和 `-e .` 必须写在同一条命令里、且钉死版本。**
`pyproject.toml` 里是 `torch>=2.4.0`，**没有上限**。单独装 `-e .` 会把 torch 升到最新，
而新版依赖 `nvidia-*-cu13`（CUDA 13），要驱动 ≥ 580——4090 机器上常见的 550 跑不了。

事后补救比你想的麻烦：cu12 和 cu13 的包会往**同一个路径写同名的 `libcudnn.so.9`**，
cu13 安装时覆盖掉 cu12 的那份；你卸掉 cu13，这个文件就被一起带走，
cu12 的清单里还记着它但文件已经没了 → `torch` 直接 import 失败。
得 `--reinstall` 强制重装整个 torch 全家才能补回来。

一条命令里钉住版本，根本不制造这个局面。

</details>

## 步骤 4：AutoDL —— 传数据 + 预下模型

### 传数据

`smoke.jsonl` / `huashu.jsonl` 是本机产物，没进 git，要单独传。配置文件跟着仓库一起来了：

```bash
# 在实例上跑：把仓库里的配置归位
cd /root/autodl-tmp/sft/销售会议抽取
cp 04_train/{qwen3_8b_qlora.yaml,infer.yaml,register_dataset.py} /root/autodl-tmp/work/
```

```bash
# 在本机跑，传数据文件
scp -P <端口> 06_data/smoke.jsonl root@<地址>:/root/autodl-tmp/work/data/
```

传不通就用 JupyterLab 拖拽上传。

> ⚠️ **Git Bash 用户注意**：`scp` 的远端路径会被 MSYS 当成本地 POSIX 路径翻译，
> `/root/autodl-tmp/...` 可能变成 `D:/GIT/Git/root/autodl-tmp/...`，文件传到一个荒唐的位置
> 而且**不报错**。加 `MSYS_NO_PATHCONV=1` 前缀关掉这个翻译。

### 预下模型（无卡模式下做，这是省钱的重点）

```bash
source ~/.bashrc      # 让 MODELSCOPE_CACHE 等变量生效
python -c "
from modelscope import snapshot_download
p = snapshot_download('Qwen/Qwen3-8B')
print('模型在：', p)
"
```

16GB。实测无卡模式下约 **11 MB/s，要 20–25 分钟**——比想象的慢，所以更不能开着 4090 等。

想看进度就另开一个终端量：

```bash
D=/root/autodl-tmp/ms_cache/models/Qwen--Qwen3-8B/snapshots/master
A=$(du -sb $D|cut -f1); sleep 30; B=$(du -sb $D|cut -f1)
echo "$(( (B-A)/1024/1024/30 )) MB/s，已下 $(( B/1024/1024 )) MB / 约 16000 MB"
```

（`snapshot_download` 自己的进度条在管道里会被缓冲住，看不到。）

> 如果报 404，去 <https://modelscope.cn/models> 搜一下当前的模型 ID，
> 填到 yaml 的 `model_name_or_path` 里。

## 步骤 6：关机 → 用 GPU 开机 → 先跑 20 步

**别直接跑完整训练。** 先用 `max_steps` 截断，20 步就能暴露 90% 的配置错误：

```bash
cd /root/autodl-tmp/work
source ~/.bashrc
llamafactory-cli train qwen3_8b_qlora.yaml --max_steps 20 --save_steps 10000
```

### 这 20 步要盯三件事

| 看什么 | 正常 | 不正常说明什么 |
|---|---|---|
| 启动日志里的 **样本数** | `num examples = 3` | 是 0 → 数据集没注册上 |
| 有没有 **截断警告** | 没有 | 有 → `cutoff_len` 太小，**必须调大重来** |
| **loss** 第一步的值 | 1.5 ~ 3.0 | >8 → template 填错了 |

> ⚠️ **截断是静默的杀手**。`cutoff_len` 小于样本长度时，LLaMA-Factory 会默默把
> 超出部分砍掉，训练照常进行、loss 照常下降，但模型学到的是「说到一半就结束」。
> 这个错误在推理时才暴露，而且看起来像是模型能力不足。

20 步跑通了，Ctrl-C 停掉，删掉 `output_dir` 重新开始。

## 步骤 7：正式训

```bash
llamafactory-cli train qwen3_8b_qlora.yaml 2>&1 | tee logs/train_$(date +%m%d_%H%M).log
```

烟测 3 条 × 20 epoch = 40 步，几分钟。正式 23 条 = 240 步，约 10–20 分钟。

**`tee` 不要省**。日志只在屏幕上，一断连就没了，而 loss 曲线是这一轮唯一的产出。

训完检查：

```bash
ls -la /root/autodl-tmp/work/saves/qwen3-8b-huashu/
# 必须有 adapter_model.safetensors（LoRA 权重）
# 还会有 training_loss.png（loss 曲线图）
```

```bash
llamafactory-cli chat infer.yaml
```

粘一条 `smoke.jsonl` 里的 `input` 进去（连【可用事实】一起）。

### 判定标准

| | 说明 |
|---|---|
| ✅ 管线通了 | 输出有「【解决问题的思路及措施】…【标准沟通话术】…」的结构 |
| ✅ 微调生效了 | 把 `infer.yaml` 里 `adapter_name_or_path` 注释掉再跑一次，**输出明显不同** |
| ❌ 微调没生效 | 两次输出几乎一样 → `template` 不一致，或 adapter 路径错了 |

**这一步的对比测试别跳过。** LoRA 加载失败时不一定报错，只是静默地什么也没变。

## 卡住了查这里

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `No matching distribution found for accelerate>=1.3.0` | **Python < 3.11**，不是网络问题 | 跑 `autodl_setup.sh`，它会自建 3.11 环境 |
| `setup.py or setup.cfg not found`（装 LLaMA-Factory 时） | pip < 21.3，不支持 pyproject 的可编辑安装 | `pip install -U pip setuptools wheel` 后重试 |
| `pip install -e .` 十几分钟没有任何输出 | pip 回溯式解析在下载候选 wheel 读元数据 | 换 uv：`python -m uv pip install --python <env>/bin/python -e .` |
| `ImportError: libcudnn.so.9: cannot open shared object file` | cu12/cu13 包同名文件互相覆盖后被卸载带走 | `uv pip install --reinstall torch==2.6.0 torchvision==0.21.0 torchaudio==2.6.0` |
| 装完 `pip list` 里有裸名 `nvidia-cublas` / `nvidia-*-cu13` | torch 被升到了 CUDA 13 版，驱动 550 跑不了 | 把 torch 版本和 `-e .` 写在同一条命令里重装 |
| SSH `Permission denied`，密码明明是对的 | 开机后端口变了，旧端口连到了别人的实例 | 重新从控制台复制登录指令 |
| 文件传到了 `D:/GIT/Git/root/...` | Git Bash 把远端路径当本地路径翻译了 | 命令前加 `MSYS_NO_PATHCONV=1` |
| `num examples = 0` | 数据集没注册 / 路径错 | 重跑步骤 5，注意用绝对路径 |
| `JSONDecodeError` | `dataset_info.json` 改坏了 | `cp dataset_info.json.bak dataset_info.json` 再重跑步骤 5 |
| `CUDA out of memory` | `cutoff_len` 或 rank 太大 | 先降 `cutoff_len`，再降 `lora_rank`。别关 `gradient_checkpointing` |
| loss 第一步就 >8 | `template` 错了 | 确认是 `qwen3_nothink` |
| loss 不降 / 是 nan | 学习率太大 | 降到 5e-5 |
| 输出说一半就停 | 训练时被截断 | 调大 `cutoff_len` 重训；推理时调大 `max_new_tokens` |
| 输出复读 | 小数据过拟合 | 调高 `repetition_penalty`，或降 epoch |
| `bitsandbytes` 报错 | 环境不兼容 | 换 A800 跑 bf16，删掉 yaml 里 quantization 两行 |
| 下模型 404 | 模型 ID 变了 | 去 modelscope.cn 搜当前 ID |
| 磁盘满 | 东西存到系统盘了 | 系统盘只 30GB。确认 `HF_HOME` / `MODELSCOPE_CACHE` 指向 `/root/autodl-tmp` |
