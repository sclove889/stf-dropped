## 一、Pipeline 设计：五档梯度基线

不要问「提示词好不好」，要问「比什么好多少」。建立**对照梯度**，用差值驱动决策。

| 档位 | 配置 | 它回答什么问题 | 实现 |
|---|---|---|---|
| **L0 裸模型** | 一句话任务描述，无提示词工程 | **下界**：提示词到底带来多少增益 | `"抽取以下字段：{schema}。输入：{text}"` |
| **L1 当前提示词** | 被测提示词（版本化存储） | **现状** | `prompts/v1.txt` |
| **L2 提示词+few-shot** | L1 + 2–3 条已标注样本作为示例 | few-shot 能补多少差距 | L1 前置 `few_shot_pool/seed_{1,2,3}.json` |
| **L3 提示词+few-shot+RAG** | L2 + 检索注入的事实 | RAG 能否治好事实编造 | L2 + `rag_retrieve(query, kb)` |
| **L4 人类专家** | **不跑模型**，直接用已标注的金标准答案 | **上界/天花板**：所有分数的标尺 | `gold_annotations/` |

### 决策全在差值里

- `L1 − L0` 小 → 提示词没做什么事，先把提示词写好
- `L3 ≈ L4` → **不要训**，提示词+RAG 已到顶
- `L3` 结构/事实过关但离 `L4` 远 → **这段差距 = SFT 理论上限**（而且是风格差距，正是 SFT 该干的活）

### L4 这档最容易漏但最重要

没有天花板，你不知道「幻觉率 18%」是糟糕还是已接近人类水平。

而且把 L4 混进盲评，能发现「专家自己标的数据有 30% 被打 C/D」这种致命问题——说明瓶颈不在模型，在标注标准不一致。

**参考来源**：
- Hamel Husain "Your AI Product Needs Evals": https://hamel.dev/blog/posts/evals/ — 三层评测框架（单元测试 / 人工评估 / A-B 测试）
- Anthropic "Demystifying evals for AI agents": https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents — "20-50 simple tasks drawn from real failures is a great start"

## 二、评测集构建

### 2.1 拆分原则

现有数据**不能既当例子又当考题**，否则测的是记忆不是泛化。

**核心张力：评测集和训练集抢同一批数据。优先级规则——**

> **评测集优先。宁可少训 50 条，不可少评 30 条。**
> 评测集不够，连「训练有没有用」都判断不了，省下来的训练数据等于白给。

#### 不随数据量变化的部分（锁死）

| 项 | 值 | 为什么不变 |
|---|---|---|
| few-shot 种子数 | **3 条** | 受限于上下文和注意力，不是受限于你有多少数据。有 1000 条也还是放 3 条 |
| 每 case 采样次数 | **3 次** | 测的是稳定性，与数据量无关 |
| 五档梯度结构 | L0–L4 | 不变 |
| 四层指标 | 结构 / 事实 / 风格 / 可用率 | 不变 |

#### 随总量 N 变化的拆分表

> **N 指专家评过、可作金标的条数（N_gold），不是原始记录总数。**

| 总量 N | few-shot | 评测集 | holdout | 余下可训 | 压力集 | 配对检验可查出的差异 |
|---|---|---|---|---|---|---|
| ~25 | 3 | 20 | — | 0 | 必造 10–15 | ~25pp（只看趋势） |
| 50 | 3 | 30 | — | 17 | 按缺口造 | ~22pp |
| 100 | 3 | 50 | — | 47 | 按缺口造 | ~18pp |
| 200 | 3 | 60 | 30 | 107 | 可能不用造 | ~16pp |
| 500 | 3 | 100 | 50 | 347 | 不用造 | ~13pp |
| 1000+ | 3 | 150 | 75 | 772 | 不用造 | ~11pp |

**三个拐点**：

- **N ≥ 150**：开始留 **holdout**。评测集反复看会被调废（fix-and-retest trap），holdout 全程只开一次，用于最终验收。
- **N ≥ 100**：评测集能做**分层抽样**（事业部 × 目录 × 问题类型按比例抽），而非随手挑。这一步的价值大于多 50 条训练数据。
- **评测集到 150 封顶**。MDE 按 √n 缩，再往上收益很小，剩余全给训练。

#### 压力集的必要性也随覆盖度变化

压力集存在的唯一目的是**补覆盖缺口**。先对 N 做一张 `问题类型 × 条数` 分布表：

- 每类 **≥5 条** → 不用造
- 每类 **<5 条** → 按缺口补到 5

不是一律造 10–15 条。没有压力集的风险：基线只测了「客诉」和「价格」，上线碰到「研发/技术痛点」直接翻车。

#### 拆分前必须确认的五件事

光知道总数不够：

| # | 要确认 | 它决定什么 |
|---|---|---|
| 1 | **N_gold**：专家评过/签过字的条数 | **只有这部分能当金标和训练数据**。N=500 但 N_gold=30，实际可用量就是 30 |
| 2 | 问题类型 × 条数分布 | 压力集造不造、造多少；能否分层抽样 |
| 3 | 事业部 × 条数分布 | 同上。某事业部只有 2 条时，是否强制塞进评测集 |
| 4 | 有无近重复（同一问题多人写过、同一话术多版本） | 近重复会在 train/test 间泄漏，并虚高有效 N。**拆分前必须去重** |
| 5 | 时间跨度 | 跨度大则风格漂移，L4 风格区间被撑宽、天花板模糊，可能需按时间段分别统计 |

**冻结纪律**：存成 `03_eval/baseline_cases.jsonl`，每条带 `case_id`，**冻结后不准改**。改了等于换考卷，前后数字不可比。

**Schema 示例**：

```jsonl
{"case_id": "eval_001", "split": "test", "inputs": {"事业部": "板带", "目录": "价格转价值", ...}, "expected": {"思路及措施": "...", "标准话术": "..."}}
{"case_id": "pressure_042", "split": "pressure", "inputs": {...}, "expected": null}
```

**参考来源**：
- Tianpan "Few-shot contamination trap": https://tianpan.co/blog/2026/06/03/the-eval-set-your-prompt-engineers-turned-into-production-few-shots — 「Grep 你的系统提示词和评测输入的 n-gram 重叠，发现了就是灾难」
- EleutherAI decontamination guide: https://github.com/EleutherAI/lm-evaluation-harness/blob/main/docs/decontamination.md

### 2.2 规模与统计功效

上一节的 MDE 列按**配对检验**口径（同一批 case 过两档，McNemar / paired bootstrap）。

**⚠️ 若改用独立样本比较，同样的 n 只能查出约 1.4 倍大的差异。** 本方案全程用配对，不要混用。

**独立样本公式**（p_baseline=0.5，α=0.05，power=0.8，n 为每组样本量）：

```
MDE = (1.96 + 0.84) × √(2p(1-p)/n)
```

| 独立样本 n/组 | MDE | 对应效应量 |
|---|---|---|
| n=50 | ~28pp | Cohen's h ≈ 0.6 |
| n=100 | ~20pp | Cohen's h ≈ 0.4 |
| n=200 | ~14pp | Cohen's h ≈ 0.3 |
| n=400 | ~10pp | Cohen's h ≈ 0.2 |

#### ⚠️ 3 次采样 ≠ 3 倍样本量

20 条 × 3 次**不是** 60 个样本。3 次是**嵌套在同一个 case 内**的重复观测，彼此不独立。

- 统计检验的单位**永远是 case**（n=20 就是 n=20）
- 3 次的作用是**降低单 case 的测量噪声**，并提供 `worst-of-3`
- 正确做法：先对每个 case 的 3 次聚合（可用率取多数票，连续指标取均值），**再**拿这 N 个聚合值进检验

把 60 当样本量会让 p 值虚低，产出一堆假的「显著」。

#### 建议

1. 评测集 < 50 时，跑完五档**只看趋势**，不做显著性检验、不声称「显著」
2. 评测集 ≥ 100 后再做正式对比与 p 值报告
3. 压力集**不参与统计检验**（无金标准答案），只做人工定性分析
4. 任何时候都优先报**置信区间**而非 p 值

**参考来源**：
- Sample size calculator: https://metricgate.com/docs/sample-size-calculator-two-proportions/
- PMC sample size guide: https://pmc.ncbi.nlm.nih.gov/articles/PMC7745163/
- Hamel "How many examples do I need": https://hamel.dev/blog/posts/evals-faq/how-many-examples-do-i-need-for-an-eval.html — 「100 traces until no new failure modes」

## 三、指标体系：自动三层 + 人工一层

### 3.1 第一层：结构合规率（全自动，秒级）

**检查项**（写死的规则）：

| 检查 | 判定 | 实现 |
|---|---|---|
| JSON 合法性 | `json.loads()` 不报错 | Python `json` 模块 |
| 必需字段完整 | `{"思路及措施", "标准话术", "备注"}` 都存在 | `required_fields.issubset(output.keys())` |
| 字段非空 | 核心字段不能是 `""` / `null` / `[]` | `all(output[k] for k in core_fields)` |
| 问题类型合法 | 在闭集 `{"价格", "交期", "客诉", ...}` 内 | `output["问题类型"] in VALID_TYPES` |
| 目录-问题类型匹配 | 查表 `CATALOG_TO_TYPES` | `output["问题类型"] in CATALOG_TO_TYPES[output["目录"]]` |

**目标**：**100%**。达不到说明约束解码没配好，或者 schema 描述有歧义，**不是指标的问题**。

**库推荐**：

### 3.2 第二层：事实幻觉率（全自动）— **核心指标**

自动抽出模型输出里所有的：

- 数字+单位（`1.1亿`、`720k`、`66.14万元`、`20%`、`50PPM`）
- 产品型号（`C7025`、`C194`）
- 认证/体系（`IATF16949`、`MES`）
- 客户/竞品名（`兴业`、`惟精`）

逐个查是否存在于**白名单**（knowledge base）。不在 = 幻觉。

```
事实幻觉率 = 未命中白名单的事实项 / 输出中全部事实项
```

**这是唯一能自动抓到「编造」的指标**。也是判断 SFT 有没有帮倒忙的唯一依据：

> **微调前后必须各测一次。如果微调后事实幻觉率上升，立刻停止** ——微调会让模型编得更自信。

**临时实现**（KB 还没建的情况）：

1. 从已评话术手工抠出所有数字/型号/认证/客户名，做成白名单表 `facts_whitelist.json`（条数越多白名单越全，误判为「幻觉」的真事实越少）
2. 用正则 + NER 从模型输出抽事实项
3. 逐项查表
4. 命中不了的 → **人工判真假**（标注到 `manual_review.jsonl`）
5. 等 KB 建好，把白名单换成 `kb.query(fact_item)`，接口不变

**抽取实现**：

```python
import re
from typing import List

def extract_facts(text: str) -> List[dict]:
    facts = []
    # 数字+单位
    facts += [{"type": "number", "value": m.group()}
              for m in re.finditer(r'\d+(?:[.,]\d+)*\s*(?:亿|万|千|%|PPM|元/吨|k)', text)]
    # 产品型号（大写字母+数字）
    facts += [{"type": "product", "value": m.group()}
              for m in re.finditer(r'\b[A-Z]\d{4,}\b', text)]
    # 认证（全大写缩写或中英混合）
    facts += [{"type": "cert", "value": m.group()}
              for m in re.finditer(r'\b(?:[A-Z]{2,}|MES|SCADA|ISO\d+)\b', text)]
    return facts
```

**参考来源**：
- Velrim extraction benchmark: https://dev.to/velrimhq/extraction-apis-invented-values-for-17-of-the-fields-that-arent-in-the-document-ours-included-3ibe — 「17% 的缺失字段被编造；陷阱字段从 54%（Mistral）到 18%（Gemini）」
- GitHub: https://github.com/velrimhq/velrim-eval
- Constrained hybrid decoding (CHyD): https://arxiv.org/abs/2609.10046 — 「硬约束限制生成为文档中连续 span，达到 near-perfect extraction faithfulness」

### 3.3 第三层：风格量化（全自动，近似指标）

业务侧自己的要求是「**定性定量，定量要用具体数据和案例说话**」，这句话直接变指标。

| 指标 | 计算 | 代码 |
|---|---|---|
| 数字密度 | 每 100 字含几个数字 | `len(re.findall(r'\d+', text)) / len(text) * 100` |
| 案例引用数 | 「案例」「某客户」「XX 家」出现次数 | `len(re.findall(r'案例\|某客户\|\w{2,4}家', text))` |
| 空话密度 | 「显著提升」「大幅改善」「优质可靠」这类无量化修饰词 | `len(空话词表 ∩ text分词) / 总词数` |

**用 L4（全部人类话术，N_gold 条）算出基线区间**：条数越多区间越窄、天花板越清晰；注意若数据时间跨度大，风格会漂移并撑宽区间，必要时按时间段分别统计。

```python
import numpy as np
from scipy import stats

# 从 L4 计算基线
l4_densities = [calc_number_density(h) for h in human_scripts]
mean, std = np.mean(l4_densities), np.std(l4_densities)
ci_95 = stats.t.interval(0.95, len(l4_densities)-1,
                         loc=mean, scale=stats.sem(l4_densities))

# 模型输出落在区间外就标红
model_density = calc_number_density(model_output)
if model_density < ci_95[0] or model_density > ci_95[1]:
    flag_as_abnormal()
```

**这层指标不是主指标**，是**辅助诊断**：L1 和 L3 的结构/事实都过关，但风格区间大面积落在 L4 之外 → SFT 成立，上限 ≈ L4 − L3 的风格差距。

### 3.4 第四层：专家可用率（人工 / LLM-as-judge 预筛）— **主指标**

**不要用 1–5 分，用四档可用性**：

| 档 | 定义 | 对应动作 |
|---|---|---|
| A | 直接可用，不改 | 通过 |
| B | 小改可用（< 5 分钟） | 通过 |
| C | 大改（骨架能留，内容要重写） | 退回 |
| D | 废弃，重写更快 | 退回 |

**主指标 = (A+B) 占比**
**辅助指标 = 单条平均评审耗时（秒）**

这两个数**直接对齐业务价值**：评审耗时从 15 分钟降到 4 分钟，这是能拿去汇报的数字；「BLEU 提升 3 个点」不是。

**LLM-as-judge 预筛**（可选，省人工）：

- 用 GPT-4 / Claude Opus 按四档标准打分
- **只作预筛**，把明显 D 档的挡掉
- **不作最终判定** —— 判官模型不知道领域事实，判不了对错

**参考来源**：
- Hamel "Binary pass/fail vs Likert": https://hamel.dev/blog/posts/evals-faq/why-do-you-recommend-binary-passfail-evaluations-instead-of-1-5-ratings-likert-scales.html — 「五档的五个问题：主观、样本量需求大、默认中间值、慢、隐藏不确定性」
- MT-Bench LLM-as-judge: https://arxiv.org/abs/2306.05685
- Position bias systematic study: https://arxiv.org/abs/2406.07791 — 「偏差因 judge/candidate/task 而异，不是随机的」
- Bias mitigation: https://arxiv.org/abs/2604.23178 — 「S8 策略（Combined Budget + Gemini 2.5 Flash）达 71% agreement, κ=0.549，成本降 15 倍」

## 四、统计严谨性

### 4.1 固定变量

基线最常见的死法是「跑完发现不可复现」。钉死这些：

```yaml
model_id: "claude-sonnet-4-20260620"  # 完整版本号，API 会静默更新
temperature: 0.7                      # 贴近实际使用，不要用 0
top_p: 0.95
prompt_version: "prompts/v1.txt"      # 版本化，不要在对话框里改
runs_per_case: 3                      # 每个 case 跑 3 次
timestamp: "2026-10-02T14:30:00Z"
```

### 4.2 每个 case 跑 3 次

「提示词不稳」本身就是要测的东西，单次采样测不出来。3 次之后你能得到：

- **均值** = 平均水平
- **方差 / 最差一次** = 稳定性

**对销售场景，最差一次比均值更重要** ——一次把假数字发给客户的代价，不会被另外两次正常输出抵消。

**所以指标要同时报 `mean` 和 `worst-of-3`**。

20 条 × 5 档 × 3 次 = **300 次生成**，API 成本很低，一两天能跑完。

**参考来源**：
- "Dice Roll Method"（温度 0.3 下的迭代次数）: https://arxiv.org/abs/2609.04047
  - 探索性 n=5（G=0.58）
  - 确证性 n=10（G=0.74）
  - 严格性 n=15（G=0.81，功效 80%）
- Background temperature at T=0: https://arxiv.org/abs/2604.22411 — 「gpt-4.1-nano T̄_bg=0.075；claude-sonnet-4 T_bg=0（100 次完全一致）」
- LLM numerical nondeterminism: https://arxiv.org/abs/2506.09501 — 浮点非结合性 / batching / 线程调度

### 4.3 盲评 + 校准锚点

人工评这步有两个必须做的动作：

1. **盲评**：打乱顺序、隐去来源（L0/L1/.../L4 标签）。专家一旦知道「这条是 AI 写的」，评分会系统性偏低。

2. **把 L4（人类自己写的 23 条）混进去一起盲评** ← **这是校准检查**

如果专家给人类自己写的话术打了 30% 的 C/D，说明**问题不在模型，在于内部对「好话术」没有共识** ——那后面所有评测数字都是噪声，得先去对齐评分标准。

**这个发现本身就值回整轮基线的成本。**

**标注者间一致性**（如果有多个专家）：

| 指标 | 何时用 | 可接受值 | 工具 |
|---|---|---|---|
| Cohen's κ | 2 个标注者，分类标签 | **≥0.67 可靠**，≥0.80 坚实结论 | `statsmodels.stats.inter_rater.cohens_kappa` |
| Krippendorff's α | ≥2 个标注者，任何数据类型，允许缺失 | 同上 | `pip install krippendorff` |

**参考来源**：
- Artstein & Poesio "Inter-Coder Agreement for Computational Linguistics": https://direct.mit.edu/coli/article/34/4/555/1999
- statsmodels Cohen's kappa: https://www.statsmodels.org/stable/generated/statsmodels.stats.inter_rater.cohens_kappa.html
- Krippendorff PyPI: https://pypi.org/project/krippendorff/
- Hamel "How many people should annotate": https://hamel.dev/blog/posts/evals-faq/how-many-people-should-annotate-my-llm-outputs.html — 「单一领域专家作 benevolent dictator，只有绝对必要才加第二个标注者」

### 4.4 显著性检验

| 指标类型 | 推荐检验 | 库 | 来源 |
|---|---|---|---|
| 二元结果（A/B 档 vs C/D 档）配对 | **McNemar's test** | `statsmodels.stats.contingency_tables.mcnemar` | Dror et al. ACL 2018 |
| 连续指标（F1、幻觉率）配对 | **Paired bootstrap resampling**（10k 次） | `scipy.stats.bootstrap` | "Please Don't Forget the CI"（LREC 2022） |
| 多模型比较 | 先 **Friedman test**（omnibus），再 Holm-Bonferroni 事后 | `scipy.stats.friedmanchisquare` + `statsmodels.stats.multitest.multipletests` | Statistical Methods for Multiple LLM Comparison |

**关键原则**（Dror et al.）：

- **Always use paired tests** when comparing on same dataset
- McNemar 专用于 2×2 列联表（TP/FP/FN/TN）
- Bootstrap / Permutation 用于不满足正态性的指标（F1、BLEU、ROUGE 等）
- Parametric t-test 只在正态分布时用（accuracy、recall 这类计数平均）

**置信区间**（比 p 值更有用）：

```python
import numpy as np
from scipy import stats
from sklearn.metrics import f1_score

rng = np.random.default_rng(seed=42)
res = stats.bootstrap(
    (y_true, y_pred),
    statistic=lambda yt, yp: f1_score(yt, yp),
    n_resamples=10000,
    confidence_level=0.95,
    method='BCa',          # bias-corrected and accelerated
    random_state=rng,
)
print(f"F1: {f1:.3f} [95% CI: {res.confidence_interval.low:.3f}, "
      f"{res.confidence_interval.high:.3f}]")
```

**多重比较校正**（5 档 = 10 次两两比较）：

```python
from statsmodels.stats.multitest import multipletests

# 10 个 p 值（L0 vs L1, L0 vs L2, ...）
pvals = [...]
reject, pvals_corrected, _, _ = multipletests(pvals, alpha=0.05, method='holm')
```

**参考来源**：
- Dror et al. "Hitchhiker's Guide to Statistical Significance in NLP": https://arxiv.org/abs/1809.01448
  - 实现：https://github.com/rtmdrr/testSignificanceNLP
- LREC 2022 "Please Don't Forget the CI": https://arxiv.org/abs/2205.11134 — 「10k bootstrap samples, BCa method」
- Multiple comparison: https://arxiv.org/abs/2608.22659 — 「K=4 models 未校正 FWER ≈ 0.26；6 models 15 次比较，5 个显著 → 校正后剩 3 个」

## 五、判读规则（先写死，再看数字）

**这一节必须在看到数字之前写死。** 否则跑完之后你一定会按着数字去凑结论。

```python
if 结构合规率 < 90%:
    决策 = "修提示词 / 约束解码。不许进入 SFT 讨论。"

elif 事实幻觉率(L1) 高 and 事实幻觉率(L3) 显著下降:
    决策 = "瓶颈是 RAG 不是 SFT。先建知识库，SFT 排后面。"

elif (A+B)率(L3) >= (A+B)率(L4) * 0.9:
    决策 = "提示词+RAG 已接近天花板（L3 达 L4 的 90%）。不训，省下卡钱。"

elif L3 结构/事实过关 but 风格区间大面积落在 L4 之外:
    决策 = "SFT 成立。理论上限 = L4 − L3 的可用率差距。"
    SFT上限估算 = f"当前 L3 可用率 {l3_ab}%，L4 是 {l4_ab}%，SFT 最多替你拿回 {l4_ab - l3_ab} 个点"

else:
    决策 = "混合瓶颈。按失败归因表分类修复（见第七节）。"
```

最后一条顺带解决了「**SFT 到底能赚回多少**」。如果 L3 的可用率已经 70%、L4 是 95%，那 SFT 最多替你拿回 25 个点 —— 而且是在有 200 条好数据的前提下。值不值得花 1 周 + 卡钱，看了这个差值才能判断。

## 六、SFT 适用性与天花板

### 6.1 什么时候该用 SFT

五个条件**全部满足**才动手：

| # | 条件 | 不满足时先做什么 |
|---|---|---|
| 1 | 结构合规率 ≥ 90% | 修提示词 / 约束解码 |
| 2 | L3（带 RAG）幻觉率已压下来 | 建知识库，SFT 排后面 |
| 3 | L3 与 L4 的差距**主要在风格语感**，不在事实 | 看失败归因表（§七） |
| 4 | 可训数据 ≥ 200 条（N_gold 扣掉评测集和 holdout 之后） | 继续攒 |
| 5 | `L4 − L3` 的可用率差值够大，值 1 周 + 卡钱 | 不值就别训 |

一句话：**SFT 是最后一道工序，不是第一道。**

### 6.2 SFT 能改什么

> 本质：**改变模型的默认行为，不改变它的知识。**

| 能改 | 说明 |
|---|---|
| **风格语感** | 默认输出就长成你要的样子，不用每次靠提示词喊 |
| **隐性规则** | 「说不清但一看就知道对不对」的东西——这是 SFT **最大的价值**，因为这类规则你根本写不进提示词 |
| **格式稳定性** | 不靠长提示词约束也能稳 |
| **成本和延迟** | 2000 字提示词压进权重，每次调用省下来 |

### 6.3 SFT 改不了什么

| 改不了 | 为什么 |
|---|---|
| **它不知道的事实** | 这是 RAG 的活。SFT 教不会新数字，**只会教它用更自信的语气编** |
| **推理能力** | 不会让模型变聪明 |
| **时效性** | 知识库更新了，权重不会跟着更新，还得重训 |
| **训练集没覆盖的场景** | 9 个问题类型只训了 3 个，另外 6 个照样翻车 |

> ⚠️ **最危险的一条**：SFT 后输出更专业、更像行家，**幻觉因此更难被发现**。
> 所以**事实幻觉率（§3.2）必须训前训后各测一次，升了就停**。

### 6.4 做完 SFT 还有多少空间

**SFT 的天花板就是 L4（人类水平）**——它是模仿，不可能超过被模仿的对象。想往上走只能换手段。

后续按性价比排序：

| 顺序 | 做法 | 为什么在这个位置 |
|---|---|---|
| **1** | **优化 RAG 召回** | 大多数项目的真瓶颈在这。检索不准，再好的模型也没料可用。而且改检索比重训便宜一个量级 |
| **2** | **数据飞轮** | 线上专家评审的 A/B/C/D 结果回流，定期增量训。这是唯一能持续涨的机制 |
| **3** | **偏好优化（DPO）** | §3.4 的 A/B/C/D 评级**天然就是偏好对**，不用额外标注。而且「挑出更好的」比「写出更好的」容易，所以它是**唯一能突破 L4 的路径** |
| **4** | **蒸馏到小模型** | 效果不涨但成本降，等效果稳定了再做 |
| ❌ | 继续堆 SFT 数据 | 收益递减最快。200 → 500 条的提升远小于 23 → 200 条 |

**什么时候该停**：当专家可用率接近 L4、且新增 100 条训练数据带来的提升**小于测量噪声**（即落在 bootstrap CI 内）时，SFT 这条路就走到头了，换第 2 或第 3 条。

## 七、失败归因表（与基线同一轮跑出）

和基线是同一轮跑出来的，不用跑两次。对 L1 的每一次失败输出打标签：

| 失败类型 | 占比 | 决定 |
|---|---|---|
| **结构飘** | ?% | → 改提示词 / 约束解码，**一周，不用 GPU** |
| **事实编造** | ?% | → 先建 RAG + 白名单，**SFT 排后面** |
| **风格飘** | ?% | → **SFT 的活**，但要先攒到 200 条 |

允许一条输出打多个标签（同时结构飘 + 事实编造）。

**实现**：评审表加一列 `failure_types: List[str]`，最后统计 `Counter(chain.from_iterable(all_failure_types))`。

## 附：一页速查

| 问题 | 答案 |
|---|---|
| 测什么 | 结构合规率 → 事实幻觉率 → 风格区间 → 专家可用率(A+B) |
| 和什么比 | L0 裸模型 / L1 当前提示词 / L2 +few-shot / L3 +RAG / **L4 人类上界** |
| 用多少条 | 3 few-shot（永远 3 条，锁死）+ 评测集（按 N 查 §2.1 表，封顶 150）+ 按缺口造的压力集；N≥150 再留 holdout |
| 拆分前先做 | **去重** → 覆盖度统计 → 确认 N_gold（只有专家签过字的能当金标） |
| 跑几次 | 每 case 3 次，报 `mean` 和 `worst-of-3`。**3 次不是 3 倍样本量**，检验单位永远是 case |
| 主指标 | **专家可用率 (A+B)%** |
| 否决指标 | **事实幻觉率**（微调后上升立刻停） |
| 怎么判显著 | 配对检验：二元用 McNemar，连续用 paired bootstrap(10k, BCa)；多比较用 Holm |
| 评测集小的时候 | <50 条只看趋势，不声称显著。20 条约能查出 ~25pp 差异 |
| 什么时候不该训 | L3 可用率 ≥ L4 的 90% |
| SFT 上限怎么估 | `L4 可用率 − L3 可用率` |
