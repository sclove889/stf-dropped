# 销售专家经验话术 —— 受控生成

> ⚠️ **本项目已于 v2 转向。** 最初按「从会议转写中**抽取**结构化表格」设计；看到真实的
> `专家经验话术汇总.xlsx` 后确认，任务实为「给定场景**生成**专家话术」。
> **请先读 [方案v2-修正版.md](方案v2-修正版.md)** —— 它取代了旧文档中关于任务定义、评测、数据的部分。

给定业务场景（行业 / 目录 / 问题类型 / 适用背景 / 客户问题），生成专家级销售话术，并沉淀为可复用知识库。

**输入 → 输出**

| | 字段 |
|---|---|
| 输入 | 事业部、一/二/三级行业、EDM产品大类、目录(4 类)、问题类型(9 类)、适用背景、问题 |
| 输出 | 解决问题的思路及措施、标准沟通话术、备注/场景定义 |

**要解决的四个痛点**

1. 抽取不准 / 漏抽
2. 分类标签体系不稳定，同一问题被打到不同类 —— *v2：标签集实为闭集，且现有 23 条数据中已发现 5 处不一致*
3. 长录音转写（上万字、多轮、口语噪声、说话人混淆）处理不了
4. 输出 JSON / schema 不守规矩、字段缺失、幻觉编造 —— *v2：**幻觉是首要风险**，且 SFT 会加重而非缓解*

## 技术选型

- **模型**：Qwen3-32B LoRA（r=64）为主，14B 作快速迭代档
- **训练**：LLaMA-Factory，Alpaca 格式，`template: qwen3_nothink`
- **推理**：vLLM + XGrammar 约束解码，`guided_json` 强制 schema 合规
- **检索**：RAG 供事实（产品参数 / 案例 / 资质 / 竞品情报），**SFT 只管风格与结构**
- **评测**：四层——结构合规率、**事实白名单命中率**、风格量化、人工评审

评测**不用** BLEU/ROUGE，理由见 [概念解释.md](概念解释.md) 第 8 节。
v1 的匈牙利匹配 + 字段 P/R/F1 是为抽取设计的，**已随 v2 转向作废**。

## 当前阶段

按 [方案v2-修正版.md](方案v2-修正版.md) 第七节，现在处于 **阶段 0（诊断）**。

三件不用 GPU、不用等数据就能做的事：

| # | 做什么 | 工期 | 为什么先做 |
|---|---|---|---|
| 1 | **冻结标签集** —— 写成 JSON，修掉表里 5 处不一致 | 半天 | 不做这个，后面全是沙上建塔 |
| 2 | **失败归因** —— 现有提示词跑 20 次，归类失败原因 | 2–3 天 | 决定后面所有投入的方向 |
| 3 | **抽事实项** —— 把 23 条话术里的数字/型号/认证抠成表 | 1 天 | 知识库第一版 + 验证第 2 层评测可行 |

**不要先租 GPU。** 提示词不稳的三种病因里只有一种归 SFT 管，
而且在事实层建好之前做 SFT 会**加重**幻觉。详见 v2 第三节。

### 并行：把训练管线先跑通

上面三件事在做的同时，可以用 3 条转录样本把 AutoDL + LLaMA-Factory 打通，
约 ¥2、1.5 小时。**目标是验证管线，不是验证模型**——等数据攒到 200 条直接复用同一套。

→ [04_train/训练操作步骤.md](04_train/训练操作步骤.md)

| 文件 | 干什么 |
|---|---|
| [04_train/autodl_setup.sh](04_train/autodl_setup.sh) | AutoDL 一键装 LLaMA-Factory（缓存自动指向数据盘） |
| [06_data/make_smoke.py](06_data/make_smoke.py) | 生成 3 条烟测样本，不依赖 xlsx |
| [06_data/xlsx2alpaca.py](06_data/xlsx2alpaca.py) | 真 xlsx → Alpaca 训练集 + 事实库种子 + 健康度报告 |
| [04_train/register_dataset.py](04_train/register_dataset.py) | 注册数据集（带校验和备份，别手改 JSON） |
| [04_train/qwen3_8b_qlora.yaml](04_train/qwen3_8b_qlora.yaml) | Qwen3-8B QLoRA 训练配置 |
| [04_train/infer.yaml](04_train/infer.yaml) | 训完看输出 + 对比未微调基线 |

**数据格式上有个设计不要随手改**：`input` 里有一个 `【可用事实】` 槽位，
装的是从 gold 输出里抠出的数字/型号（oracle RAG）。这样模型学的是
「用给你的事实」而不是「在这个位置编个数字」。等知识库建好，把 oracle 换成检索结果即可，
格式不用动。

## 已知局限与风险

| | |
|---|---|
| 🔴 **最高风险** | 用 23 条带具体数字的样本 SFT，模型会学到「此处该放一个具体数字」却不知该放哪个 → 编出格式完美的假数字。**比微调前更危险。** |
| 🟡 数据量 | 已评 23 条，按问题类型切开每类 1–6 条。长文本生成 SFT 需 ~300 条起步 |
| 🟡 数据一致性 | 23 条人工数据中 `问题类型` 已有 5 处不一致（含同 sheet 内相邻两行不一致） |
| 🟡 行业树不完整 | `一级行业` 层级未定义，需补全后才能做逐级约束 |
| ⚪ CSDS | 原作抽取任务代理，v2 转向后**已不适用**，相关脚本与步骤保留仅作参考 |
